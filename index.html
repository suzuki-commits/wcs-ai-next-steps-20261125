FROM WCS伺った現状

  • 問い合わせメールが届くとスプレッドシートに起票され、回答案が生成される仕組みは動いている。
  • ただし、生成される回答文の精度が低い。現場の実感として、業務の改善までは至っていない。
  • 参照用シートに、よくある問い合わせや過去の対応を追加して充実させた。それでも文章の改善は見られなかった。
  • 公式サイトなどを参照していないことが原因ではないか、というお見立て。
  • 小栗社長の許可のもと、問い合わせメールをAIアシスタント「Muse」とつなぎ、返信の下書きを作らせる方法を試している。こちらのほうが便利。
  • ただしMuseは佐藤様個人のアカウントに紐付くため、チームでの運用には載せにくい。
  • Claudeは使っているが、本格的な活用はこれから。
  • 繁忙期を抜けたので、いまのうちに来年に向けた準備を進めたい。

FROM COMIX弊社からお伝えしたこと

  • この1年で Claude Code／Codex の性能が大きく上がった。情報の置き場所を指定し、AIに直接見に行かせる設定にすれば、回答文の精度は改善が見込める。
  • 5月時点の Google Apps Script による実装より、現在は Claude Code／Codex のほうが適している。
  • 提案資料の料金表は、全項目を積み上げる金額ではない。月額30万円で5つのご提案すべてに伴走する。
  • いまの性能であれば、12か月ではなく6か月ほどで大半をやり切れる見込み。3か月での区切りもご相談できる。
  • 音声・動画の生成、会社の記録をAIが行き来する仕組みなど、現在できることを実演。
  • 最初の安全設定（作業範囲・禁止操作・実行前チェック）が重要。設定資料一式をお渡しする。

How We Fix It

問い合わせAIを、どう直すか

本日伺った3つの困りごとに、そのまま対応する形で組み直します。5月に決めた「送信は必ず人が確認する」方針は変えません。

観点 いま 作り直したあと
AIが見る情報 参照用シートだけ。追記しても文章が良くならなかった。 公式サイト、過去の問い合わせ履歴、FAQ、イベント別の資料を、AIが直接読みに行く。
使える人 便利な下書き作成は、佐藤様個人のアカウントでしか使えない。 チームで共有する置き場所に設定をまとめ、担当のみなさまが同じ品質で使える。
返信の下書き 5月に「必ず人が直すので二度手間」として対象から外した。 精度が上がれば、下書きは手間を減らす側に回る。新旧を実際の問い合わせで比べ、戻すかどうかを決める。
良し悪しの判断 現場の実感。 実際に届いた問い合わせを質問セットにして、直す前と後を同じ基準で比べる。

Safety First

最初に整える、3つの安全設定

Claude Code はパソコンの中のファイルを直接扱える道具です。使い始める前に、次の3つを一緒に設定します。

作業する範囲を決める

決めたフォルダの中だけで作業させます。範囲の外には手を出せないので、ほかのデータに影響しません。

やってはいけないことを決める

削除や、鍵となる情報の読み取りなど、禁止する操作を先にリストにしておきます。

実行の前に検査する

AIが操作を実行する直前に、危ない操作が混ざっていないかを自動で確認する仕組みを入れます。
